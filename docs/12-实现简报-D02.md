# D02 实现简报：QQ 官方通道探针与身份绑定

本简报是自包含实现契约。实现者只改下文列出的文件；不得改动其他产品设计文档、不得改动既有工具语义。

## 背景与边界

- 产品决策已定：手机通知走腾讯官方 QQ 机器人 C2C（私聊）接口；不入群、不监听原群、不读用户历史消息。微信只做独立探针，不在本任务范围。
- 官方接口契约（已核验）：
  - 取访问令牌 `POST https://api.bot.qq.com/app/getAppAccessToken`，body `{ "appId": "...", "clientSecret": "..." }`，响应含 `access_token`、`expires_in`。
  - 发单聊 `POST https://api.bot.qq.com/v2/users/{user_openid}/messages`，头 `Authorization: QQBot <access_token>`，body 文本消息 `{ "content": "...", "msg_type": 0 }`。
  - 主动推送不带 `msg_id`/`event_id`；`is_wakeup` 与两者互斥。2xx 只代表「已受理」，不代表手机显示。
  - 官方参考：<https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html>、<https://github.com/tencent-connect/dsh-qqbot>
- 入站事件（`C2C_MESSAGE_CREATE` 等）由官方 dsh-qqbot 插件负责，NightDesk 不实现 WebSocket/Webhook 网关。本任务的探针必须明确区分「NightDesk 自己能证明的」与「需要官方插件或用户操作才能证明的」。

## 目标

在 `packages/dsh-nightdesk` 内加入可复跑的 QQ 通道能力探针与身份绑定，使「QQ 通道是否真的可用、可用到什么程度」成为一条可查证记录，而不是口头声明。

## 验收标准

1. `node --test packages/dsh-nightdesk/test` 全绿，现有测试数量不减少；新增测试不少于 10 项。
2. 新增迁移 `schema_version=3`，至少包含：
   ```sql
   CREATE TABLE IF NOT EXISTS channel_bindings (
     id TEXT PRIMARY KEY, owner_id TEXT NOT NULL, channel TEXT NOT NULL,
     app_id TEXT, external_id TEXT NOT NULL, display_name TEXT,
     bound_at TEXT NOT NULL, last_verified_at TEXT, last_error TEXT,
     created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
   CREATE UNIQUE INDEX IF NOT EXISTS channel_bindings_unique
     ON channel_bindings(owner_id, channel, app_id, external_id);

   CREATE TABLE IF NOT EXISTS probes (
     id TEXT PRIMARY KEY, owner_id TEXT NOT NULL, kind TEXT NOT NULL,
     started_at TEXT NOT NULL, finished_at TEXT,
     status TEXT NOT NULL,                    -- pass | partial | fail
     capabilities TEXT NOT NULL,              -- JSON 数组
     host_version TEXT, plugin_version TEXT,
     notes TEXT, created_at TEXT NOT NULL);
   ```
3. 新增 `src/probe.js`，导出：
   - `createQqProbe({ fetch, now, config })` → `{ run(options) }`；
   - `probeCapabilities` 至少要覆盖五项，每项输出 `{ id, state, detail, evidence }`，`state ∈ 'verified' | 'missing' | 'blocked' | 'unverified'`：
     1. `credential`：用 appId/clientSecret 换取 access_token 是否成功（失败要区分缺凭据 / 凭据被拒 / 网络失败）。
     2. `proactive_text`：向绑定的 openid 发送一条主动文本消息；记录 HTTP 状态与业务 code，`state='verified'` 的含义严格限定为「服务端受理」。
     3. `passive_reply`：仅在检测到官方入站网关可用时可能为 `verified`；本插件自身无法接收事件，因此默认 `blocked`，`detail` 说明需官方 dsh-qqbot 插件提供 `msg_id`。
     4. `attachment`：当前未实现附件发送，固定 `missing` 并写明缺口。
     5. `binding`：本地身份绑定是否已建立且最近验证通过；未绑定为 `missing`。
   - `run()` 不得抛错；任何异常都转成 `fail` 结果并写入 `probes`，保留原始错误信息（脱敏后）。
4. 新增 `src/probes-store.js` 或在 `store.js` 中提供方法：`recordProbe(record)`、`latestProbe(kind)`、`listProbes({ kind, limit })`、`bindChannel({ channel, appId, externalId, displayName })`、`channelBindings()`、`verifyBinding(id, at)`。
5. 新增工具（风格与现有 `definition()` 一致，原生 JSON Schema，自己校验参数）：
   - `nightdesk_probe_qq`：参数 `{ sendTest?: boolean }`。默认 `sendTest=false`，只验证凭据与绑定，不发真实消息；`sendTest=true` 时才发一条明确标注测试的消息。返回写入后的探针记录（含 `capabilities`）。
   - `nightdesk_probes`：参数 `{ kind?: string, limit?: number }`，返回最近探针记录。
   - `nightdesk_channels`：返回通道与绑定概览（channel、appId、openid 掩码、bound_at、last_verified_at），绝不回显 secret 或完整 openid（最多显示前 3 位与后 4 位）。
   - `nightdesk_bind_channel`：参数 `{ channel: 'qq', appId: string, openid: string, displayName?: string }`，写入绑定并返回掩码后的记录。
6. 隐私与安全：日志、返回值、`error_detail`、`notes` 中不得出现 `clientSecret`、`access_token`；测试必须断言这一点。openid 只允许掩码展示。
7. 测试不得访问真实网络：所有 HTTP 通过注入的 `fetch` 假实现；覆盖成功、业务 code 非 0、HTTP 500、401、缺凭据、网络异常六种情形。
8. 纯 ESM JavaScript、零第三方依赖、不得 import 任何 `@deepseek-ai/*`；不做 commit/push。

## 期望产出

- 探针一次运行即落一条 `probes` 记录；重复运行不覆盖历史，只追加。
- `nightdesk_probe_qq` 在无凭据时返回 `status='fail'` 且五项能力逐条给出 `missing` 与所需环境变量名（`QQBOT_APPID`、`QQBOT_SECRET`、`QQBOT_OPENID`），不抛错、不伪造通过。
- 绑定建立后，探针的 `binding` 能力据 `last_verified_at` 判定通过与否。
