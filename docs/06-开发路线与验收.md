# 06 开发路线与验收

2026-11-13 · 规划工作量不是日期承诺；所有阶段尚未实施。

[首页](../README.md) · [连接器](04-来源与连接器.md) · [评估](08-决策与证据.md)

## 1. 开发方向

先让少量来源、一个手机通道、一个运行时真正工作，再扩自动化。不要先造复杂审批平台而迟迟不能处理一条真实消息，也不要只做通知后忘掉 Agent 管理。

早期单人单宿主、固定连接器、固定工具清单和任务内显式偏好。跨项目记忆、原生 App、更多 IM、团队协作和自主规则学习后置。安全通过减少动作面减负，不靠删权限检查。

## 2. 阶段与依赖

| 阶段 | 交付范围 | 做到什么算通过 | 粗估有效人日 |
| --- | --- | --- | --- |
| P0 验证前提 | 固定 dsh 版本、专用 profile；验证渠道、会话、存储和调度入口 | 一条真实私聊输入、一个手机提醒通道、两个测试会话均有探针证据 | 2—4 |
| P1 → v0.1 防漏事 | 主动转发、时间确认、今日清单、手机提醒、人工完成 | 一条真实通知完成闭环；关闭页面、锁屏、重启和模型故障下已确认提醒仍走真实手机路径；改期或完成后旧提醒失效 | 5—8 |
| P2 → v0.2 双主线原型 | 至少两个选定 dsh 会话的只读状态、待决和成果汇总 | 真实会话标明读取时间、范围和断线缺口；区分等待输入、审批阻塞、空闲与业务完成，原生审批仍回宿主 | 5—8 |
| P3 → v0.3 最小总助理 | 一个 worker 完成本地草稿，支持核对、最多两轮返工、变更和停止 | 跑通目标→委派→核对→修改→交付；身份与版本检查、旧 attempt 拒绝、停止和成果核对通过 | 4—7 |
| P4 → v0.4 真实试用 | 连续个人使用、失败分析、效果记录与竞赛材料 | 至少 7 个自然日保留真实使用、失败、人工负担和成本记录，再决定扩展项 | 5—10 |

P0—P3 合计粗估 **16—27 个有效人日**，P4 另计 **5—10 人日**。估算假设一位熟悉 TypeScript 的开发者，另有人员协助样本标注和手机观察；等待授权、环境排障和学习成本另计。范围收紧并复用 dsh 只缩短首版路径，不代表远期功能已经完成，也不能据此倒排竞赛交稿日期。

依赖顺序为 **D00 → D01；D01 后 D02 与 D03 并行；D01 → D04 → D05；D02、D05 → D06；D03、D05 → D07；D07 与委派探针 → D08**。P0 同时证明入口、手机通道和 dsh 只读路径，P1 必须包含 D06，不能把手机提醒推迟到后一阶段。

竞赛目标争取 v0.3；窗口不足时交付真实可用的 v0.2，并明确受管执行尚未完成。实现范围控制在单人、单宿主、选定会话白名单。QQ 先作为私聊转发候选，微信独立验收，不要求机器人入群或监听原群；学习平台自动只读研究不阻塞主线。

## 3. 开发工作包

| 任务 | 工作内容 | 依赖与验收 |
| --- | --- | --- |
| D00 固定环境 | 记录宿主、Node、包管理器、渠道版本和 profile 方案 | 留下可复现版本记录与初始化验证命令 |
| D01 插件骨架 | 最小插件、只读健康工具、加载与卸载 | 依赖 D00；卸载后无残留监听和定时器 |
| D02 QQ 通道探针 | 私聊文字、转发、附件、主动推送、身份绑定 | 验证实际收发范围；失败时明确缺失能力，微信另行探针 |
| D03 会话探针 | 两个选定 dsh 测试会话的状态、事件、重连和读取范围 | 依赖 D01，可与 D02 并行；不把可见日志当成可控制会话 |
| D04 最小存储 | 原始证据、事项版本、Outbox、幂等和恢复 | 依赖 D01；模拟中断后恢复且不重复处理；宿主事务能力不足才引入插件自有 SQLite |
| D05 事项闭环 | 文字导入、日期候选、确认、今日查询 | 依赖 D04；关键歧义保留待确认，不静默补成确定截止 |
| D06 手机提醒 | 持久到期发送、有限重试、故障状态 | 依赖 D02、D05；实测锁屏、重启、断网和模型故障，已确认提醒有确定性真实手机路径 |
| D07 工作汇总 | 选定 dsh 会话进入今日、待决和成果查阅 | 依赖 D03、D05；原生审批仍在宿主处理 |
| D08 单 worker 执行 | 本地草稿委派、核对、最多两轮返工、变更与停止 | 依赖 D07 和委派探针；版本改变后拒绝旧提交 |

插件和 preset 的目录在 D00 按 dsh 实际加载方式确定，测试至少区分 contracts 与 scenarios。当前不预建 apps/web、apps/server 或多包 packages 工程，也不把规划目录当成已有代码。

| T35 | 事项改期、取消或人工完成后旧提醒到期 | 旧调度失效，不发送过期提醒；已在途结果进入对账 | P1 |

## 5. 通过条件和测量

安全与语义案例中，不允许未授权执行、把未知写成成功、旧提交覆盖当前交付；出现一次就不开放对应动作。手机 gate 要求真实记录，但一次成功不证明长期送达率。

P0 准备至少 **20 条**脱敏或合成样本，覆盖时间歧义、冲突、重复和解析失败；手机先做至少 **10 次**排障记录，保留所有失败。冻结金标、指标分母和风险分级后再确定召回与误报阈值，不能跑完再选阈值。这些样本用于发现问题，不能据此宣称长期送达率，也不编造 95% 等目标已达成。

关键事项召回和来源覆盖分开；日期正确、未知和错误确定化分开；通知提交、接受、设备显示、打开分开。记录误打断、主动操作分钟、质量、费用、失败和弃用。

A 原工作方式，B 助理，C 在工具权限资料可比时作为强单 Agent 补充。配对节时率与失败处理见证据文档，不只统计成功任务。

## 6. 演示和协作

演示先展示来源与期限核对、手机提醒，再展示至少两个真实 dsh 会话的只读汇总与原生待决定位，最后展示一个 worker 的本地成果和一次变更。真实连接、回放与合成数据明确标识。

真人负责需求观察、数据授权、质量标注、真实试用与展示。AI 辅助编写和生产不能替代这些证据。工程实现应拆为小而自包含任务，分别给目标、约束、绝对路径、产物和可执行验证；主审回收验证。
