## 1. 开发方向

先让少量来源、一个手机通道、一个运行时真正工作，再扩自动化。不要先造复杂审批平台而迟迟不能处理一条真实消息，也不要只做通知后忘掉 Agent 管理。

早期单人单宿主、固定连接器、固定工具清单和任务内显式偏好。跨项目记忆、原生 App、更多 IM、团队协作和自主规则学习后置。安全通过减少动作面减负，不靠删权限检查。

## 2. 阶段与依赖

| 阶段 | 交付物 | 必过条件 | 估算有效人日 |
| --- | --- | --- | --- |
| P0 需求与探针 | 真实工作流、脱敏金标、来源/手机/运行时报告、冻结首版范围 | 真实痛点与至少一可行来源、手机通道、运行时路径 | 4—8 |
| P1 消息和期限 | 主动分享、少量站点、时间确认、今日清单、通知、健康 | 关键歧义不漏；页面关闭锁屏真实观察；持久恢复 | 10—18 |
| P2 运行时只读 | 一个固定版本真实会话状态、摘要、统一待决 | 非模拟会话、读取范围、过期状态与原生审批边界验证 | 8—15 |
| P3 受管任务 | 任务图、0/1/N worker、核对返工、Manifest、最小授权动作 | 迟到、停止竞争、回执未知、授权变更测试通过 | 15—28 |
| P4 扩展和实用验证 | 更多来源、可选登录试验、个人使用与竞赛材料 | 新增连接器独立验收；实际效果逐项报告 | 10—25 |

以上是假定开发者熟悉 TypeScript 并复用成熟组件的粗估；等待授权、设备兼容和学习时间可能增加。不能把总和直接当比赛截止前可完成承诺。

P0 的运行时和手机探针必须先做，P2 适配器可与 P1 并行；正式 P2 依赖通用身份、证据和队列。P1+P2 才称双主线原型，P3 才宣称受管执行。

若竞赛窗口不足，交付有真实连接和清晰限制的 P1+P2；规划中的 P3 标后续，不用录屏或模拟声称已实现。

## 3. 开发工作包

- **K0 证据与门槛**：收一条真实漏事路径、一条多会话管理路径，按来源范围建立金标；冻结关键事项定义与验收分母。
- **K1 基础工程**：固定运行时/依赖、类型检查、迁移、身份、对象存储、事件/Outbox、备份恢复。尚无代码时命令仅计划，初始化后才固定真实命令。
- **K2 采集与事项**：主动输入先跑通；随后一个网站列表/详情/附件；实现时间候选、去重候选、来源健康和人工纠正。
- **K3 手机闭环**：持久调度、去重、有限重试、静默规则、端到端时间证据；不以页面 Toast 代替。
- **K4 运行时**：固定版本探针→只读桥→事件续读→待决归一化→返回宿主。未完成前不开放控制。
- **K5 有界执行**：先无副作用任务、成果核对与版本；再接一个可控制动作，做授权和未知对账，不同时接多平台写入。
- **K6 个人使用**：使用日志、失败记录、配对任务、费用、演示与公开复用说明。

建议未来目录为 apps/web、apps/server、packages/domain、packages/connectors、packages/runtime、packages/storage、tests/contracts、tests/scenarios、docs。只是结构建议，当前没有这些代码。

## 5. 通过条件和测量

安全与语义案例中，不允许未授权执行、把未知写成成功、旧提交覆盖当前交付；出现一次就不开放对应动作。手机 gate 要求真实记录，但一次成功不证明长期送达率。

P0 冻结金标、指标分母和风险分级后确定召回与误报阈值，不能跑完再选阈值。当前未有足够样本，不编造95%等目标已达成。

关键事项召回和来源覆盖分开；日期正确、未知和错误确定化分开；通知提交、接受、设备显示、打开分开。记录误打断、主动操作分钟、质量、费用、失败和弃用。

A 原工作方式，B 助理，C 在工具权限资料可比时作为强单 Agent 补充。配对节时率与失败处理见证据文档，不只统计成功任务。

## 6. 演示和协作

演示先展示来源与期限核对、手机提醒，再展示一个真实会话进入队列，最后展示受管成果和一次变更。真实连接、回放与合成数据明确标识。

真人负责需求观察、数据授权、质量标注、真实试用与展示。AI 辅助编写和生产不能替代这些证据。工程实现应拆为小而自包含任务，分别给目标、约束、绝对路径、产物和可执行验证；主审回收验证。
