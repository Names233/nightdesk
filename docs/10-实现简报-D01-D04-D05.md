## dsh 插件契约（已核实源码，勿臆造）

- 入口模块导出：`export const name = 'nightdesk'`；`export const inject = ['tools']`；
  `export function apply(ctx) {...}`。
- 注册工具：
  ```js
  ctx.tools.register({
    name,
    description,
    parameters, // 原生 JSON Schema
    output: {
      schema,   // 原生 JSON Schema
      render(args, value) { return [{ type: 'text', text: '<给模型看的字符串>' }] },
    },
    execute: async (args, exec) => ({ /* lossless JSON value */ }),
  })
  ```
- `parameters` / `output.schema` 必须是**原生 JSON Schema**对象（不是 DSL）：
  参数根 `{type:'object', properties:{...}, required:[...]}`；
  output.schema 如 `{type:'object', properties:{...}, additionalProperties:true}`。
- **registry 不校验 parameters**（只有 `defineTool` 会），execute 内自行校验并抛 `Error`，
  消息带字段名与错误码。
- **不要 import `@deepseek-ai/dsh-tools` 或任何 `@deepseek-ai/*` 包**（profile 解析不到）。
  只用 node 内置模块：`node:sqlite`、`node:path`、`node:os`、`node:crypto`、`node:fs`。
- 清理：用 `ctx.effect(() => () => store.close())` 或 `ctx.on('dispose', ...)` 关闭数据库；
  不得留下定时器/监听器（D01：加载、卸载无残留）。

## 存储（D04，`node:sqlite` DatabaseSync，WAL）

- 数据目录：`process.env.NIGHTDESK_DATA_DIR`，否则 `path.join(os.homedir(), '.dsh', 'nightdesk-data')`；
  库文件 `nightdesk.db`；目录 `mkdirSync(..., {recursive:true})`。
- 开库后：`PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON; PRAGMA busy_timeout=5000`。
- `meta` 表存 `schema_version=1`；迁移用幂等 `CREATE TABLE IF NOT EXISTS`。
- 表结构（SQLite 存 ISO-8601 文本，字段名与 docs/03 对应）：
  - `observations(id TEXT PK, owner_id TEXT, source_id TEXT, source_label TEXT, raw_text TEXT, content_hash TEXT, occurred_at TEXT, created_at TEXT)`
  - `items(id TEXT PK, owner_id TEXT, observation_id TEXT, title TEXT, due_at TEXT NULL, due_date TEXT NULL, time_zone TEXT, precision TEXT, time_status TEXT, completion TEXT, confirmed INTEGER, version INTEGER, created_at TEXT, updated_at TEXT)`
    - `time_status ∈ resolved|unknown|ambiguous|conflicted|canceled`
    - `completion ∈ unconfirmed|manual_complete|source_complete|conflicted`
    - `precision ∈ instant|day|unknown`
  - `item_versions(id INTEGER PK AUTOINCREMENT, item_id TEXT, version INTEGER, snapshot_json TEXT, changed_at TEXT, reason TEXT)`：每次写 items 都追加一行
  - `outbox(id TEXT PK, event_id TEXT, handler_id TEXT NULL, type TEXT, payload_json TEXT, status TEXT, attempts INTEGER, available_at TEXT, created_at TEXT)`：唯一索引 `(event_id, handler_id)`；`item.confirmed` / `item.completed` 与业务更新**同一事务**写入
  - `audit_events(id TEXT PK, at TEXT, actor TEXT, action TEXT, item_id TEXT NULL, detail_json TEXT)`
  - `idempotency(key TEXT PK, scope TEXT, request_hash TEXT, response_json TEXT, created_at TEXT)`：同 key 同 hash 返回原响应；同 key 异 hash 抛 `IDEMPOTENCY_CONFLICT`
- `owner_id` 默认 `process.env.NIGHTDESK_OWNER ?? 'local'`。
- 时间一律 UTC RFC3339（`new Date().toISOString()`）；展示与「今天」判定用 `Asia/Shanghai`。

## 日期抽取（D05，`src/dates.js`，纯函数可单测）

`extractDeadline(text, now)` 返回 `{ timeStatus, dueAt, dueDate, precision, matchedText, basis }`；
时区固定 `Asia/Shanghai`，用 `Intl.DateTimeFormat` 求当地日期，禁止手写时区偏移。

| 输入形态 | 结果 |
| --- | --- |
| `2026-11-20`、`2026/11/20`、`2026年11月20日`、`11月20日`、`11/20` | `resolved`，`dueDate` 有值，`precision='day'`，`basis` 记 `literal` / `assumed-year` |
| `今天/明天/后天/大后天` | `resolved` + dueDate，`precision='day'` |
| `今晚/明晚/明早/今晚之前`（日期可定、时刻不定） | `timeStatus='ambiguous'`，dueDate 可给，**dueAt 必须 null**（T02：不假造倒计时） |
| `本周五/这周五/周五/下周一` | `resolved` + dueDate；`basis` 记 `explicit-this-week` / `assumed-future-week`；跨周计算正确 |
| `月底/下周/尽快/过几天/近期` | `ambiguous`，dueDate/dueAt 均 null |
| 无任何时间词 | `unknown`，全 null |

多个时间词：取第一个可解析的，`matchedText` 保留原文片段。

## 工具（`src/tools.js`，名称前缀 `nightdesk_`，中文 description）

1. `nightdesk_health`：无参数。返回 `{ok:true, pluginVersion:'0.1.0', schemaVersion, dataDir, dbPath, timeZone:'Asia/Shanghai', nowUtc, counts:{observations,items,outboxPending}, readOnly:false}`。
2. `nightdesk_capture`：参数 `{text(必填,string), sourceLabel?(默认'manual'), sourceId?, occurredAt?(RFC3339), idempotencyKey?}`。
   原文**逐字**存 observations（`content_hash=sha256`）；按行/句切分，每段抽日期生成候选事项 `confirmed=0`；
   无时间词的段也建候选（`unknown`）。返回 `{observationId, candidates:[{itemId,title,dueDate,dueAt,timeStatus,precision,matchedText,needsConfirmation,version}], totals}`。**不自动确认**。
3. `nightdesk_items`：参数 `{view?: enum[today,pending,all] 默认 today, includeUnconfirmed?: 默认 true, limit?: 1..100 默认 50}`。
   `today` 按 Asia/Shanghai 当天 `due_date`（或 `due_at` 落在当天）筛；`pending` 排除 `completion != 'unconfirmed'`。
   返回 `{view, asOfUtc, readScope:{timeZone,limit}, items:[...], counts}`。
4. `nightdesk_confirm`：参数 `{itemId(必填), expectedVersion(必填 integer), dueDate?, dueAt?, title?, timeStatus?: enum[resolved,unknown,ambiguous]}`。
   CAS：`UPDATE items SET ... WHERE id=? AND version=?`；未命中抛 `VERSION_CONFLICT`（含当前 version）；
   成功 version+1、`confirmed=1`，写 item_versions / audit_events / outbox（`item.confirmed`）。
5. `nightdesk_complete`：参数 `{itemId, expectedVersion, completion?: 默认 'manual_complete'}`。
   CAS 同上，写 `item.completed` outbox；已 canceled 拒绝。
