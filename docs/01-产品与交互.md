# 01 产品与交互

## 1. 用户和问题

目标用户是同时处理个人事务和多个 Agent 会话的人。首位观察对象可以是项目发起者，但不能把个人经历包装成全体学生的统计结果。

两条主要工作流：从分散消息发现应办事项和机会；把交给 dsh、Codex 的工作推进到可用成果。前者关注漏事、期限、出处，后者关注方案阅读、审批、上下文切换和成果核对。两者共享用户目标、时间和注意力，但保留各自证据与控制边界。

不以校园活动筹备替代原问题，也不为了演示强行把简单任务拆成两个 Agent。先观察真实使用路径，再决定每条路径需要多少自动化。

## 2. 助理工作循环

理解目标 → 查明已有事实 → 制定有界计划 → 安排执行 → 核对成果 → 更新下一步。

工作说明包含期望成果、约束、输入、授权范围、费用上限和完成规则。已有信息充分、行动在授权内时继续；会改变成本、正确性、影响范围或副作用的重要缺口才提问。

自然语言可以创建目标和说明偏好，但外部材料中的指令不会成为用户授权。用户选择一个方案，也不自动批准发送其中的消息或公开发布成果。

主助理对汇总负责。它不能把所有 worker 原话堆给用户；应说明现在完成了什么、证据在哪里、剩余什么以及是否需要本人行动。

## 3. 五个入口

| 入口 | 默认内容 | 可展开内容 |
| --- | --- | --- |
| 聊天 | 交代目标、纠正、暂停、追问 | 计划、假设与推理依据的可说明摘要 |
| 今日 | 关键事项、推进中任务、需要本人做的事 | 排序理由、时间证据 |
| 待决 | 问题、推荐、选项后果 | 来源、授权对象和版本 |
| 成果 | 当前交付包与限制 | 验证记录、沿用条目、worker 引用 |
| 来源健康 | 成功范围、缺口与通道状态 | 最近尝试、游标、附件错误 |

不因产品采用聊天入口就让用户每次必须开启新对话。今日清单和待决链接定位到持久对象，聊天只解释和控制它们。

## 4. 四类卡片

事项卡：标题、原始来源、时间解释、当前处理进度、完成证据和下一提醒。无法直达原文时提供用户保存的证据视图，不编造深链。

决定卡：一次解决一个真正阻塞的问题，说明推荐和代价。若已有偏好且不越权，助理可以直接形成草稿并解释选择，不强求每次出现个人决策。

授权卡：工具、精确目标、执行身份、参数预览、不可逆影响、有效期与一次性动作。展示内容与真实执行内容绑定；内容改变需要重新核验。

异常卡：说明发生什么、当前状态、影响哪些工作和下一步。不能把采集失败写成没有新通知，把工具超时写成已失败或已完成。

## 5. 通知规则

普通更新汇入用户设定的每日摘要；早晚两次和普通每日五次额度只是可调整初值，不是已验证最优策略。关键期限、关键日期歧义和影响覆盖的严重故障走独立规则，不被普通额度或兴趣过滤压制。

已确认期限可采用提前一天和提前六小时等可配置梯度，需考虑用户实际准备耗时。潜在关键期限时间不确定时先提醒核对，不显示假精确倒计时。

提醒按事项版本、原因和升级级别去重。同一原因有有限重试和升级预算，超过后留在显著待办并汇总通道故障；不能无限轰炸，也不能静默丢弃。预算耗尽不改变事项的关键性。

静默时段由用户明确设置；关键提醒是否突破必须单独说明并获得选择。推迟提醒需要展示推迟到何时及可能错过的风险，超时永不成为动作批准。

手机通知默认只含安全摘要与入口。发送服务接受不等于手机显示；打开不等于完成。页面关闭、锁屏、换网、断网恢复和订阅失效分别验证。已确认提醒在模型故障或额度耗尽时仍须沿确定性路径发送：先探针宿主能力，不足时由插件以持久 dueAt、事务 Outbox 和有限重试补足；应用内待办不能代替真实手机验收。

## 6. 时间、修订和完成

期限保存原文、发布日期、观察时间、解释时区、解析基准和候选时间。缺少本周五或今晚的基准时标为未知，不能偷偷用入库日期补齐。只有日期但无具体时刻时保留日期精度，不默认承诺 23:59；必要时确认。

延期、取消和撤回保留新旧证据。新公告明确引用旧公告时建立修订关系；没有关系证据时保留冲突候选。相似标题不证明同一事项，更晚抓取不证明更权威。

个人进度与平台状态分开。用户标记完成是一条个人声明；平台提交回执是一条来源证据。作业通知不证明未提交，报名通知不证明余量。完成、已读、已提醒是三个不同维度。

已过期未完成的事项继续可见，进入补救或归档选择，不能因为超过截止自动消失。可恢复误标完成，修改有审计，旧通知不能覆盖新确认。

## 7. 三个贯穿场景

**分享作业截图**：记录图片和来源说明，提取课程与期限。若只有今晚截止但缺消息日期，突出核对时间；用户确认后安排提醒。用户标记完成，显示人工完成，不能写平台已提交。

**发现兴趣活动**：只在来源覆盖内推荐，解释命中哪个显式兴趣、时间是否冲突。课表不完整时显示冲突检查范围。可建立准备任务，报名本身默认由用户操作；没有余量证据不报剩余名额。

**接管工作视图**：读取已验证可见的 Agent 会话，识别待输入、执行中与已交付。只读层给摘要与返回宿主入口；受管层才能继续自己拥有的任务。核对成果后交付，不能把空闲当成功。

## 8. 个性化和首次使用

首次只需分享一条消息、一个网站或一个目标。补充课程、组织、兴趣、课表和通知偏好都是可选；未知偏好保持未知，不根据一次点击永久屏蔽某类事项。

显式偏好与推断偏好分别记录，附来源、更新时间、适用范围与删除入口。默认任务内偏好，跨项目记忆作为后续能力，不能把私人内容无差别放进每次提示词。

首次看到有用事项的时间、设置负担和后续纠错都要实测。五分钟只是探索目标，不是当前承诺。

## 9. 分版本边界

- **v0.1 防漏事**：主动转发、时间确认、今日事项、真实手机提醒和人工完成形成闭环；改期、完成或取消后旧提醒失效。
- **v0.2 双主线原型**：在 v0.1 上加入至少两个真实 dsh 会话的只读状态、待决和成果汇总。等待输入、审批阻塞、空闲与业务完成必须区分，原生审批仍回宿主处理。
- **v0.3 最小总助理**：一个 worker 完成本地草稿，支持委派、核对、最多两轮返工、变更和停止；旧 attempt 不能覆盖当前成果。首版不以多 worker 或外部写入为必要条件。
- **v0.4 真实试用**：至少 7 个自然日记录使用、失败、人工负担和成本，只评价已验证能力。

整个 Agent 工作层运行在一个 dsh 业务插件、助理 preset 和专用 profile 内。QQ 是首个私聊转发候选，微信独立探针，v0.1 不要求两个渠道同时完成，也不要求机器人入群或监听原群。输入按文字、单张截图、公开链接逐步开放；收到转发只证明助理收到材料，不证明平台任务已经完成。学习通与雨课堂自动只读接入是独立研究线，不阻塞首版。

不做代签到、代考试、无限自动审批、无差别读取私人聊天。自动回复、报名或提交只有在未来具备明确授权、真实接口和对账能力后逐项开放。
