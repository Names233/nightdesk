# 05 Agent 运行时

2026-11-13 · 设计草案，未验证多 Agent 比单 Agent 更好。

[首页](../README.md) · [契约](03-数据与接口契约.md) · [路线](06-开发路线与验收.md)

## 1. 主助理负责什么

维护目标、约束、已知事实、依赖、预算和下一步。已授权且信息充分的工作继续；影响正确性、成本、外部副作用的重要缺口才形成待决。消息汇总为此服务，不能取代工作推进。

任务说明包含成果、输入引用、允许工具、范围、完成规则和验收方式。模型提出任务图；代码检查循环依赖、无授权工具、预算超限和无法核验的完成条件。

零 worker 用于查询状态和规则排序；一个是普通任务默认；多个只用于独立工作。初始并行上限建议三，子 worker 默认不可递归委派，上限由预算和实际测量决定。

## 2. 输入与输出

输入包含 taskId、attemptId、goalVersion、输入版本、租约、工具能力和输出契约。外部原文标为不可信材料，不能把网页中的执行要求提升成系统指令。

输出包括工作总结、Artifact 引用、Observation 引用、验证结果、未解决项和用量。工具结果独立记账，自然语言完成声明不是回执。

secretRef 留在本地工具层解析，worker 不持有可导出的凭据。通过创建子任务或转述用户授权不能扩大范围。

## 3. 三层接入

| 等级 | 能做什么 | 允许声明 |
| --- | --- | --- |
| L1 readonly | 读取经过验证可见的会话、状态、成果 | 看得见；最后读取时间明确 |
| L2 managed | 创建、管理自己拥有的任务 | 派得动；取消能力单独验证 |
| L3 controlled actions | 为具体工具经过真实控制入口派发 | 此动作可受保护；不覆盖外部旁路 |

适配器发布细粒度 capability，不因为有 thread/read 就声称能批准或停止任意会话。命令与事件协议通过版本化映射层转换，不依赖宿主内部数据库可写。

建议事件信封：runtimeId、runtimeVersion、externalSessionId、externalEventId、cursor、occurredAt、observedAt、capability、payloadRef。序列缺口和重放显式处理；会话 idle 不等于目标成功。

## 4. Codex 与 dsh

Codex 官方 app-server 描述 thread/list、thread/read、thread/start 与审批事件等集成方向。固定版本后验证身份、线程可见性、加载与续订、事件重放、工作目录和取消；不能假定一个新 app-server 接管已开 CLI 或 App。

humanCommand 检查点需按实际版本协商 experimentalApi 与 requiredHumanApproval，普通或会话级批准不可代替必须由本人处理的检查点。无兼容连接时按原协议拒绝，不伪造成功。

dsh 为快速变化的 developer preview。优先正式插件/公开服务接口，探针读取范围和事件，再验证受管创建与跟进。没有接口证据时不写“能直接复用类型”。

无法远程处理原生审批，就把用户引回正确宿主、定位请求并保存阻塞原因。返回入口也需验证，不生成不存在的 URL。所有宿主原有权限和保护保留。

## 5. 核对与返工

结构检查文件与必填项，证据检查来源和时间基准，内容检查需求覆盖和逻辑一致。规则、模型和人工按风险组合；同一段回答自称已检查不算独立审查。

默认任务最多两轮返工，反馈指明具体缺口和修复标准；耗尽后保留已完成部分和未满足条件，不无限互相审查。费用、尝试和耗时同时约束。

最终交付经 Manifest 核对后发布。用户默认读综合成果，可追溯 worker 输出，但不要求逐条消化过程日志。

## 6. 版本、租约与沿用

领取时授予 lease 和递增 fencingToken。提交时匹配当前 attempt、goalVersion、租约与版本 CAS。租约失效后旧进程可能仍在计算，但不能提交当前成果。

用户变更沿字段和任务依赖传播，未知依赖保守失效。未影响 Artifact 可经再验证沿用，在新 Manifest 记录理由与适用版本，不改旧正文。

计划变化不抹除外部执行账本。已经发出的动作即使归属旧版本仍可能成功或未知，必须独立展示和对账。

## 7. 决策、授权和继续

Decision 是选哪条路径；Approval 是具体工具、目标、身份、参数、版本、有效期和 actionId 的执行许可。选择方案不是授权全部外部动作。

服务端 canonicalize 意图并计算哈希。授权消费、一次性派发资格和执行账本更新为一个事务；派发前复验策略 epoch、停止状态、期限和哈希。原生审批继续单独满足。

减少重复确认依靠明确作用域的既有授权和真正不需要人决策的自动继续，不依靠猜同意、超时或模型自报低风险。规则不能覆盖宿主强制本人检查点。

## 8. 停止与未知结果

暂停不启动新任务与外部动作，保留在途计算结果待恢复核验。停止撤销 pending、granted 和未取得派发资格的 token，并请求支持取消的运行时取消。

停止与派发争同一个事务门。停止先提交则拒派；派发先取得资格则可能已发出，不保证撤回。界面展示仍在途与未知动作。

超时进入 reconciling/unknown，先查提供方回执、目标状态或人工确认。只有证明未执行且仍有授权才可重新派发，不承诺精确一次。

## 9. 持续跟进

触发器为期限、来源修订、依赖完成、用户选择、授权过期或租约异常，不靠无休止自我聊天。例行检查受预算和退避限制。

汇总显示最后读取时间和覆盖范围。没有新事件不等于已空闲，已空闲不等于交付合格；任务仍有明确完成规则。
