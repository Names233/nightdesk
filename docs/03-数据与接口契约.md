## 1. 通用约定

实体共有 id、ownerId、createdAt；可变实体有 version、updatedAt。时间采用 RFC 3339 UTC，事项解释时区独立保存。ownerId 来自服务端认证上下文。

创建无需 expectedVersion；修改已有实体需要 expectedVersion。目标语义变更还需所依据的 goalVersion。实体 version 与目标 goalVersion 不混用。冲突返回 409，不最后写入覆盖。

副作用命令使用 Idempotency-Key，唯一范围为 ownerId、方法、规范化路由、key。保存 canonical body hash 和原响应：同 key 同 body 返回原结果，同 key 异 body 返回 409。幂等记录过期不能授权重发未知动作。

## 2. 实体、关系和唯一约束

下表是跨阶段的长期契约，不要求 P1 一次实现全部实体。P1 只落地事项、证据、提醒、来源健康和必要 Outbox；P3 再增加目标、任务、attempt、Artifact 与 Manifest。

| 实体 | 关键字段 | 关系与约束 |
| --- | --- | --- |
| Source | kind、locator、accessMode、capabilities、secretRef、pollPolicy、health | ownerId+sourceKey 唯一；不存明文凭据 |
| Observation | sourceId、externalId、revisionKey、originalRef、contentHash、publishedAt、observedAt、ingestedAt、rawTimeText、cursor | sourceId+externalId+revisionKey 唯一；原文不可变 |
| ItemDeadline | type、title、evidenceIds、timeStatus、candidates、timezone、resolution、completion、progress | 多对多关联 Observation；关键字段有证据 |
| ProfileFact | kind、value、origin、scope、confirmedAt、expiresAt | 显式与推断分开；可撤销和删除 |
| Goal | objective、constraints、goalVersion、budget、dependencyRevision（后续）、status、currentManifestId | 当前语义版本单调递增 |
| Task | goalId、objective、inputDependencies、dependsOn、outputContract、state、currentAttemptId | 图必须无环；任务不是尝试；显式字段依赖后续扩展 |
| TaskAttempt | taskId、goalVersion、attemptNo、status、usage；leaseOwner、leaseUntil、fencingToken（通用扩展可选） | taskId+attemptNo 唯一；v0.3 校验身份、当前 attempt 与版本 |
| Artifact | producingAttemptId、producingGoalVersion、contentRef、contentHash、format、evidenceIds | 内容不可变；修订创建新记录 |
| DeliveryManifest | goalId、goalVersion、entries、validation、status、publishedAt | 条目引用 Artifact；沿用带再验证 |
| Decision | question、options、selection、evidenceIds、goalVersion、status | 选择不授执行权 |
| Approval | actionId、intentHash、identityRef、goalVersion、policyEpoch、expiresAt、status | 每次具体动作唯一有效授权 |
| ActionExecution | actionId、canonicalIntent、approvalId、status、dispatchTokenHash、providerReceipt、reconciliation | actionId 唯一；未知结果独立保留 |
| Notification | subjectRef、reason、channel、dedupeKey、scheduleDueAt、runtimeSessionRef、status、providerReceipt、deviceEvidence、readAt、completedAt | ownerId+channel+dedupeKey 唯一；各段证据分开记录 |
| AuditEvent / Outbox | seq、eventId、type、subject、version、payloadRef | eventId 唯一；消费 eventId+handlerId 唯一 |

Source.health 包括 lastAttempt、lastSuccess、cursor、gap、lastError、coverage。成功仅指声明范围，首页成功不等于历史完整。观察编辑、删除与转载使用关系记录，不覆盖原证据。normalizedHash 用于相似判断，不替代原字节 contentHash。

ItemDeadline.timeStatus 为 resolved、unknown、ambiguous、conflicted、canceled；保存原文和候选时间各自来源。日期精度与时刻精度分开。completion 为 unconfirmed、manual_complete、source_complete、conflicted；个人进度单独记录。

## 3. 状态和不变量

Goal：collecting、ready、active、blocked、paused、completed、stopped、archived。Task：blocked、ready、running、awaiting_input、validating、succeeded、failed、canceled、superseded。

v0.3 Attempt：queued、running、awaiting_input、validating、succeeded、failed、canceled、superseded。通用执行扩展可增加 leased、expired；租约失效只撤销提交资格，不断言外部进程停止。

Manifest：staging、validating、published、superseded、withdrawn。Decision：open、selected、obsolete、withdrawn。Approval：pending、granted、consumed、denied、expired、revoked。

后续 ActionExecution：planned、awaiting_approval、dispatchable、dispatching、succeeded、failed、reconciling、unknown、canceled。dispatching 超时可能进入 unknown，不归入 superseded。

Notification：queued、submitting、accepted、delivered、read、failed、unknown、canceled。不支持回执时不擅自置 delivered；读回执可证明用户已打开但不证明任务完成。调度到期、投递会话、渠道接受、手机显示、用户打开、事项完成分别记录事实和时间，不能压成一个“已送达”状态。

分阶段必须保持：

1. v0.3 的旧 attempt 或过期 goalVersion 不能提交当前成果；完整 lease/fencingToken 后续扩展。
2. v0.3 目标变更使相关未完成工作失效；显式字段依赖图后续扩展，未知依赖保守处理，不能仅让模型猜测。
3. Artifact 正文不可变；后续未影响成果沿用必须再验证，Manifest 不能无检查混合版本。
4. 外部动作开放时，授权绑定具体动作、参数、身份、版本、策略 epoch、有效期。
5. 已派发与未知外部动作不能被计划变更或任务停止抹去。
6. 通知已读、人工完成与平台确认分开。
7. 所有者检查、版本检查和状态转换在插件与宿主的确定性代码中落实。

## 4. 分阶段接口面

首版优先实现 dsh 插件工具和业务事件，不强求独立 HTTP 服务。若后续轻量视图或远程集成需要 HTTP，再沿用以下路由语义；工具名在初始化时固定，不能把这些目标接口当成已实现能力。

| 路由 / 工具语义 | 用途与并发 | 阶段 |
| --- | --- | --- |
| POST /api/v1/observations/import | 主动转发；幂等 key、来源和原始证据 | P1 |
| GET /api/v1/inbox | 今日和核对队列；身份过滤、排序理由 | P1 |
| PATCH /api/v1/items/{id} | 时间确认、个人完成；expectedVersion | P1 |
| GET /api/v1/sources/health | 来源与通知覆盖缺口 | P1 |
| GET /api/v1/events | 增量事件、权限过滤和 cursor | P1/P2 |
| POST /api/v1/goals | 创建本地草稿目标；幂等 key | P3 |
| PATCH /api/v1/goals/{id} | 目标变更；expectedVersion、goalVersion | P3 |
| POST /api/v1/goals/{id}/control | pause、resume、stop；expectedVersion | P3 |
| GET /api/v1/goals/{id}/delivery | 当前成果和验证 | P3 |
| POST /api/v1/internal/attempts/{id}/artifacts | 身份、版本、内容哈希与旧 attempt 拒绝 | P3 |
| POST /api/v1/sources | 更多来源配置；幂等 key，locator 校验 | P4 评估后按扩展决定 |
| POST /api/v1/decisions/{id}/select | expectedVersion、goalVersion；不执行动作 | 外部动作开放时 |
| POST /api/v1/actions | 固化意图；幂等 key、goalVersion | 外部动作开放时 |
| POST /api/v1/approvals | 请求一次动作授权；幂等 key | 外部动作开放时 |
| POST /api/v1/approvals/{id}/grant | 本人确认；expectedVersion 和身份校验 | 外部动作开放时 |
| POST /api/v1/approvals/{id}/deny | 本人拒绝；expectedVersion | 外部动作开放时 |
| POST /api/v1/actions/{id}/dispatch | 内部执行身份；策略与停止复验 | 外部动作开放时 |
| POST /api/v1/internal/tasks/{id}/claim | 服务身份；事务领取，按需加入租约与 fencing | 通用执行扩展时 |

列表返回 nextCursor、hasMore、coverage。游标失效报缺口，不能用空列表伪装无更新。越权对象统一按 404 策略处理，内部服务接口不向普通浏览器开放。

## 7. 错误与重放

新 key 配旧版本返回 409 VERSION_CONFLICT，携带 currentVersion、currentGoalVersion 与重新读取提示。同已成功 key 同 body 返回原响应，不增版本；同 key 异 body 返回 409 IDEMPOTENCY_CONFLICT。

其他错误：403 APPROVAL_EXPIRED、409 GOAL_STOPPED、409 STALE_ATTEMPT、422 VALIDATION_FAILED、409 BUDGET_EXHAUSTED。包络含 requestId、code、message、retryable 和必要版本，不暴露凭据或他人资料。

## 8. 后续外部动作的授权和派发原子性

服务端按版本化算法生成 canonicalIntent，覆盖 actionId、工具、目标、参数、身份、goalVersion、有效期。计算 intentHash 并绑定 policyEpoch。任何关键变化重新核验，不相信 Agent 提供的摘要。

授权消费、令牌登记、执行账本更新在同事务完成。消费后到真正派发前再检查目标停止状态、epoch、有效期与哈希。停止撤销 pending、granted 和尚未取得派发资格的令牌。

停止与派发竞争共同事务门。先取得派发资格者可能已经离开进程，不能保证撤回；停止先提交则不得取得资格。外部调用不与数据库原子，因此超时先对账，不盲重发，不宣传精确一次。

## 9. 暂停与恢复

暂停停止新任务调度和新外部派发；在途计算可结束并暂存，但不自动发布或触发后续动作。恢复复验版本、权限、预算与来源新鲜度，有效授权可沿用到其原有效期，失效需重新确认。

停止撤销后续执行资格并保留已派发账本，不原地改回 active。继续相同工作应建立明确的新执行计划和新授权；不会因此重做 unknown 动作。

## 10. DSH 宿主引用与主动转发

运行时引用统一保存 runtimeId、profileId、dshSessionId、dshEventId、runtimeVersion 和 capability snapshot；它们不替代 goalId、taskId 或 attemptId。用户主动转发的 Observation 保存 sourceType=forwarded_message、forwardedBy、原始附件引用、source quote 与 observedAt，不扩展为群或账号授权；首版直接复用现有导入语义，不新增等价转发路由。dsh ID 只用于追溯，不能直接授予业务控制权。

会话观察记录保存 ownerId、dsh sessionId、label、addedAt、lastReadAt、lastSeq、lastEventAt、lastEventType、status 和 error。刷新结果必须同时给出 found、live、persisted、capturedThroughSeq、eventCount、inheritedEventCount、lastEvent 与 readAt；宿主只读面没有运行状态字段时，`runState` 固定为 `unknown`，并保留 `runStateReason`，不能从事件内容推断运行或审批状态。
