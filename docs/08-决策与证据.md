## 1. 主要决策

| 决策 | 当前选择 | 原因及复审条件 |
| --- | --- | --- |
| 产品主轴 | 一个人的消息、目标与 Agent 工作助理 | 同时解决漏事与多会话负担；若只剩提醒需回查覆盖 |
| 应用形态 | 一个 dsh 业务插件+助理 preset+专用 profile | 复用宿主会话、工具、审批与停止，不重复建设独立前后端；持续查看需求出现后再加轻量视图 |
| 业务存储 | 宿主事务存储优先，插件自有 SQLite 兜底 | 事项更新与 Outbox 必须同事务，不直接写 dsh 内部数据库 |
| 模型职责 | 理解/建议/有界规划/内容核对 | 状态权限仍由代码；模型更新不能改变边界 |
| worker | v0.3 一个 worker，后续按需扩展 | 先验证本地草稿闭环，多 Agent 有协调成本，不预设并行数量 |
| 接入顺序 | QQ 主动转发优先，手机与 dsh 只读探针并行 | 微信独立验收；不以封闭渠道未证实接口或机器人入群作为成立前提 |
| 手机提醒 | P0 先探针，P1 必过端到端验收 | 网页待办不解决关闭页面后的漏事 |
| 成果 | 本地不可变内容+再验证 Manifest | v0.3 保留版本一致性；跨目标精确沿用后续验收 |
| 动作 | 后续明确授权+ledger+对账 | v0.3 只交付本地草稿；外部副作用不能保证精确一次 |

后续变更新增决策记录：背景、备选、理由、证据、迁移影响与回退，不悄悄覆盖原约束。

## 4. 证据层次

文档阅读→能力探针→端到端测试→真实使用评价，四者分别记录。文档只能支持方向；探针固定版本与身份范围；端到端包含设备或宿主最终表现；使用评价才回答是否有用。

当前只有设计与资料阅读，可说拟支持、推荐架构，不能说已稳定接入、不会漏事、已节省多少时间。所有样例明确合成，不伪造访谈或测评。

## 5. 配对评估协议

A 是原工作方式，B 是拾光哨；任务配对尽量保持难度、输入、权限、工具和质量要求，记录熟练度、顺序和环境。C 仅在可比时加入强单 Agent，不可比则单列。

第 i 对主动人工节时率：s_i = (t_A,i - t_B,i) / t_A,i，要求 t_A,i>0。主动时间含阅读、切换、选择、核对与恢复，不含纯等待；等待另报。报告每对差值、s_i 中位数与范围，不混用两组中位数降幅。

失败、弃用、回到原流程和额外修复保留；未完成单列质量失败/未完成，不用删除样本制造节时率。首次设置与日常使用成本分开，调参和评价样本分开，顺序交叉或随机化。

关键事项召回分母为声明覆盖范围内金标，另报总来源覆盖；未接入群不掩盖。日期报告正确、未知和错误确定化；通知报告提交到设备各段证据；质量看需求、事实、可追溯与可用性。

成本包括模型、外部通道、运行与人工核对；未知账单标估算。小样本逐项报告，不把无显著差异当质量等效，不先承诺固定 30% 效果。

开源基础与团队新增分开。规划不算已完成模块，AI 生产不替代真人需求观察、授权、质量标注和真实试用。演示区分实际连接、合成输入和回放。

## 8. DSH 底座修订

整个 Agent 层以 DeepSeekRuntime（dsh）为唯一宿主，复用 profile、plugin、session、event、tool 和 approval；NightDesk 只补事项、证据、期限、提醒、工作汇总与成果核对等业务能力。工程起点是一个业务插件、一个助理 preset 和一个专用 profile，不再把独立 Fastify/React 服务作为首版前提。

QQ 与微信采用主动转发优先的私聊入口，QQ 先探针、微信独立验收；学习通与雨课堂自动只读接入仍是 Web 优先、官方 APK 后补证的独立研究线。当前 dsh、腾讯渠道、学习平台和真实手机投递均未在 NightDesk 产品内完成实测，本路线不构成已接入或已达成的声明。
