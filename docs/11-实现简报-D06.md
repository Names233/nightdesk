# D06 实现简报：到期提醒与投递（Outbox 消费者 + 调度 + 通道适配）

本简报是自包含实现契约。实现者只改下文列出的文件；不得改动现有工具语义与文档。

## 目标

在 `packages/dsh-nightdesk` 内补齐「到期提醒 → 投递 → 状态机」闭环，使已确认事项在到期时能真实投递到用户手机通道（通道由配置选择，默认 console），并且改期/完成/取消后旧提醒不再发送。

验收标准：

1. `node --test packages/dsh-nightdesk/test` 全绿（现有 16 项不得减少，新增不少于 12 项）。
2. 新增表 `notifications`、`deliveries`（字段见下），`outbox_event_handler` 作为消费者游标表使用。
3. 调度 tick 由插件启动（`setInterval`，默认 15 秒），`ctx.effect` 清理时停表并 close store，加载/卸载无残留。
4. 三态分离：`scheduledAt`（调度时刻）、`acceptedAt`（通道受理）、`deliveredAt`（用户设备确认）；只把通道 2xx 记为 `accepted`，绝不记 `delivered`（T12）。
5. 改期后旧提醒 `canceled` 且不再投递（T35）；完成/取消事项同理。
6. 崩溃恢复与重放：同一 `(item_id, version, kind)` 只生成一条提醒，重启后不重复投递（T15/T34）。
7. 通道失败按指数退避重试（10s/30s/2min，最多 5 次），超过后 `failed`，并写 audit_events（T33：模型不可用不影响已确认提醒）。

## 约束

- 纯 ESM JavaScript，零第三方依赖，不得 `import` 任何 `@deepseek-ai/*` 包（宿主版本不匹配）。
- 存储用 `node:sqlite`（Node 24 内置），延续现有 WAL + `BEGIN IMMEDIATE` 事务风格。
- 所有时间为 RFC3339 UTC 字符串；日历/时区逻辑留在 `dates.js`，不要在 `scheduler.js` 里重算时区。
- 不改 `tools.js` 已有五个工具的名称与参数契约；只新增工具。
- 不联网、不在测试里发真实 HTTP 请求；通道用注入的 `fetch` 实现，测试传 fake。
- 不写 dsh 内部数据库；数据目录沿用 `NIGHTDESK_DATA_DIR` 或默认 `~/.dsh/nightdesk-data`。

## 期望产出

新增文件：

- `src/channel.js`：通道适配器。导出 `createChannel(config, deps)` 返回 `{ name, send(message) }`。只支持两种 `kind`（不提供通用 webhook/第三方推送）：
  - `console`：写 `deliveries.error_detail = 'console'`，返回 `{ ok: true, channelMessageId: 'console-<n>' }`（默认，便于无凭据测试）。
  - `qqbot`：QQ 官方机器人接口——先 `POST https://api.bot.qq.com/app/getAppAccessToken`（`{ appId, clientSecret }`）取 `access_token`，再 `POST https://api.bot.qq.com/v2/users/{openid}/messages`，头 `Authorization: QQBot <token>`，体 `{ content, msg_type: 0 }`。这是**主动推送**语义（不带 `msg_id`/`msg_seq`/`is_wakeup`）；成功判定为 2xx 且（`code === 0` 或 无 `code` 且有字符串 `id`），2xx 只代表渠道受理、不代表手机已显示；失败记录响应体前 500 字（脱敏 secret/token）。
  - 凭据只从 `channel.json` 或环境变量读取，日志与返回值不得回显 secret。
- `src/scheduler.js`：`createScheduler({ store, channel, now, setInterval, clearInterval })`，导出 `{ start, stop, tick, scheduleForItem, cancelForItem }`。
  - `scheduleForItem(item, dueAt)`：`INSERT OR IGNORE` notifications，唯一键 `(item_id, version, kind)`；`kind` 默认 `due`。
  - `tick()`：取 `status IN ('queued','retry') AND next_attempt_at <= now` 的行，逐条 `UPDATE ... SET status='submitting'`（条件更新防并发），调 `channel.send`，按结果写 `accepted`/`retry`/`failed`，并写 `deliveries`。
  - `cancelForItem(itemId, reason)`：把该事项所有 `queued/retry/submitting` 置 `canceled`，写 audit_events。
- `src/outbox.js`：`consumeOutbox({ store, handlers, limit })`，按 `created_at` 升序取未处理事件，同一 `(event_id, handler_id)` 只用 `outbox_event_handler` 记一次；handler 抛错不阻塞后续事件，返回 `{ processed, skipped, failed }`。
- `test/scheduler.test.js`、`test/channel.test.js`、`test/outbox.test.js`：覆盖上述验收 3—7 条，至少 12 项。

修改文件：

- `src/store.js`：新增迁移 `schema_version=2`：
  ```sql
  CREATE TABLE IF NOT EXISTS notifications (
    id TEXT PRIMARY KEY, owner_id TEXT NOT NULL, item_id TEXT NOT NULL,
    item_version INTEGER NOT NULL, kind TEXT NOT NULL,
    due_at TEXT NOT NULL, scheduled_at TEXT NOT NULL,
    status TEXT NOT NULL, attempts INTEGER NOT NULL DEFAULT 0,
    next_attempt_at TEXT, accepted_at TEXT, delivered_at TEXT,
    canceled_at TEXT, cancel_reason TEXT, channel TEXT,
    created_at TEXT NOT NULL, updated_at TEXT NOT NULL);
  CREATE UNIQUE INDEX IF NOT EXISTS notifications_unique ON notifications(owner_id, item_id, item_version, kind);
  CREATE TABLE IF NOT EXISTS deliveries (
    id TEXT PRIMARY KEY, notification_id TEXT NOT NULL, attempt INTEGER NOT NULL,
    channel TEXT NOT NULL, status TEXT NOT NULL, http_status INTEGER,
    channel_message_id TEXT, error_detail TEXT, started_at TEXT NOT NULL, finished_at TEXT);
  ```
  并把 `confirm/complete` 改为在同一事务内调用调度器回调（通过 `store.onItemChanged` 事件或返回待办事件，不要在 store 内 import scheduler，避免循环依赖）。
- `src/index.js`：构造 store → channel → scheduler → consumeOutbox 定时（每 30 秒）+ scheduler.start()，全部包在 `ctx.effect` 内清理。
- `src/tools.js`：新增 `nightdesk_remind`（参数 `itemId` 必填、`dueAt` 可选、`kind` 可选）、`nightdesk_reminders`（`status` 可选、`limit` 可选）、`nightdesk_tick`（手动触发一次 tick，便于人工验证）、`nightdesk_channel`（返回通道名与配置是否齐全，绝不回显 secret）。工具注册风格与现有 `definition()` 一致。
