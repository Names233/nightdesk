# 18 验收脚本（手工走一遍）

本文把 `docs/06` 里的验收案例落到「点什么、看什么」的粒度。自动化测试覆盖了契约层（`node --test packages/dsh-nightdesk/test`，当前 102 项）；下面这些必须在**真实宿主 + 真实手机**上做，测试替代不了。

前置：按 [安装与助理 preset](16-安装与助理preset.md) 起服务，打开 `http://127.0.0.1:5593/?token=...`，新建一个会话。

---

## 1. 事项闭环（T01 / T02 / T03 / T06）

| 步骤 | 说什么 / 调什么 | 期望 |
| --- | --- | --- |
| T01 | `nightdesk_capture` 正文：「周五 18:00 交结构力学作业」 | 候选里 `timeStatus=resolved`，`dueAt` 是具体 UTC 时刻 |
| T02 | 「今晚把实验报告写完」 | `timeStatus=ambiguous`、`dueAt=null`，**不猜**成 23:59 |
| T03 | 再 capture 一条「周末有空看看摄影展」 | 兴趣类不进「今日」，关键作业不被过滤掉 |
| T06 | 对已确认事项 `nightdesk_confirm` 改期到更晚，再 `nightdesk_items` | 旧提醒被取消，只有新时间一条 `queued` |

## 2. 提醒真机（T12 / T13 / T15 / T33 / T35）

需要 `NIGHTDESK_QQBOT_APP_ID` / `NIGHTDESK_QQBOT_CLIENT_SECRET` / `NIGHTDESK_QQBOT_OPENID`，并且机器人已是好友、你允许了主动消息。

1. `nightdesk_probe_qq { "sendTest": true }` —— 五项能力里 `credential` 与 `proactive_text` 应为 `verified`；如果 `blocked`，看 `notes` 里的官方错误码。
2. `nightdesk_remind` 给一件 2 分钟后到期的事项建提醒，`nightdesk_tick` 立即触发一次。
3. 看状态：`nightdesk_reminders` 里应出现 `accepted`（服务端受理），**不是** `delivered`；手机关通知、关页面再跑一次，状态仍停在 `accepted` —— 这就是 T12「受理 ≠ 手机显示」。
4. T13：锁屏放着不动，到点看手机是否真的响；没响就记成「未验证」而不是「已送达」。
5. T35：提醒 `queued` 后改期，旧的 `next_attempt_at` 应被取消，只发新时间那一条。

## 3. 会话只读汇总（T16）

1. 在这个 profile 里开两个会话，各说点不同的事（一个问作业，一个让它整理笔记）。
2. `nightdesk_session_watch` 把两个会话加入观察，`nightdesk_sessions { "refresh": true }` 拉一次。
3. `nightdesk_overview` —— 「最近完成」段每一条都要带 `readAt` 与 `range`；`runState` 必须是 `unknown`（宿主不提供运行态）。
4. 反例检查：任何一个会话的产出都不能被写成「已完成」，除非它真的 `completion=manual_complete`。

## 4. 受管委派（T20 / T21 / T22 / T27）

一次完整流程（括号里是期望）：

```
nightdesk_task_create { "objective": "把结构力学第三章整理成 10 条要点", "acceptance": ["每条要点不超过 80 字"], "allowedTools": ["nightdesk_items"] }
  → 返回 task.id（version=1）、goalVersion=1
nightdesk_task_start { "taskId": "<id>" }
  → 返回 attemptId；再调一次拿到同一个 attemptId（幂等）
nightdesk_task_submit { "taskId": "<id>", "attemptId": "<aid>", "draftText": "...", "expectedTaskVersion": 1 }
  → task.version 变 2，artifact.sha256 与正文一致
nightdesk_task_review { "taskId": "<id>", "attemptId": "<aid>", "verdict": "pass", "structure": {"ok": true}, "evidence": {"ok": true}, "content": {"ok": true} }
  → task.status=accepted
```

逐条对照：

- **T20**：上面这套只在你说「交给它做」时发生；单纯问「今天有什么」不应该出现 `task_create`。
- **T21**：`requestChange` 把 `goalVersion` 推到 2 后，旧 attempt 再 submit → `STALE_ATTEMPT`，任务 `goal_version` 已是 2。
- **T22**：用旧 `attemptId` 或旧 `expectedTaskVersion` 提交 → `STALE_ATTEMPT` / `VERSION_CONFLICT`，**已有成果不被覆盖**（`nightdesk_tasks` 里 version 没变）。
- **T27**：`nightdesk_task_stop` 之后立刻 submit → `TASK_STOPPED`，`task_artifacts` 里没有新增行。
- 返工：连续两次 `verdict=needs_revision`（每次至少一条 finding），第三次 → `REVIEW_ROUNDS_EXHAUSTED`，任务 `exhausted`，历史 review 仍可查。
- 越权：`allowedTools` 里写 `nightdesk_task_submit` 或 `subagent` → `RECURSIVE_DELEGATION`；写不存在的工具 → `UNAUTHORIZED_TOOL`。
