# D07 实现简报：工作汇总（只读总览）

本简报是自包含实现契约。实现者只改下文列出的文件。

## 背景

NightDesk 的聊天入口要能回答四件事：今天有什么、哪些还在等我拍板、委托出去的事走到哪、消息来源还健康吗。这份总览必须是**只读**的、带读取时间与范围的，且不能把「渠道受理」说成「我已看到」。

产品口径（已定，不得改）：
- Notification 的 `accepted`（QQ 服务端受理）≠ `delivered`（手机显示）≠ `read`（用户打开）。总览里只能声称已知的那一层。
- 宿主会话只能给出只读快照；`runState` 一律 `unknown`，不得声称「正在运行/等待审批」。
- 不伪造控制：总览不得暗示 NightDesk 能取消、改期、替用户在宿主里操作。

## 前置

`src/sessions-probe.js`（D03）已存在并提供 `refresh({ ownerId, sessionIds? })`；`src/store.js` 已有 `watched_sessions` 表与 `listWatchedSessions({ ownerId })`。若你的工作区里 D03 尚未落地，先按 `docs/13-实现简报-D03.md` 核对接口再实现本任务，不要自造不兼容的接口名。

## 目标

新增一个只读汇总工具，把「事项 / 待决 / 成果 / 来源健康 / 会话快照」拼成一份带 `readAt` 与 `range` 的结构化响应。

## 验收标准

1. `node --test packages/dsh-nightdesk/test` 全绿；现有测试数量不减少；新增测试不少于 8 项。
2. 新增 `src/overview.js`，导出 `createOverview({ store, sessionProbe, now, config })` → `{ build(options) }`，`build({ ownerId, refreshSessions })` 返回：
   ```json
   {
     "readAt": "2026-11-14T14:30:00Z",
     "timeZone": "Asia/Shanghai",
     "today": { "date": "2026-11-14", "items": [ ... ], "range": { "scannedItems": 12 } },
     "pending": { "items": [ ... ], "channels": [ ... ], "sessions": [ ... ], "range": { "scannedItems": 12 } },
     "recent": { "since": "2026-11-07T00:00:00Z", "items": [ ... ], "range": { "scannedItems": 12 } },
     "health": { "channels": [ ... ], "sessions": [ ... ], "range": { "sessionsWatched": 2 } }
   }
   ```
   - `today.items`：`dueAt` 落在本地「今天」的、未完成事项，按 `dueAt` 升序；每项含 `id`、`title`、`dueAt`、`timeStatus`、`completion`、`version`。
   - `pending.items`：需要用户拍板的候选事项——未确认（`status='candidate'`）、或 `timeStatus ∈ unknown|ambiguous|conflicted`、或 `completion='conflicted'` 的已确认事项；按更新时间升序，最多 20 条。
   - `pending.channels`：最近一次 QQ 探针 `status != 'pass'` 时的待办提示（缺凭据 / 投放失败），无则空数组。
   - `pending.sessions`：观察名单里上次刷新 `status != 'read_ok'` 的会话（`not_found`/`read_failed`）。
   - `recent.items`：最近 7 天完成的事项，按 `updatedAt` 降序，最多 20 条，标明 `completion`（`manual_complete`/`source_complete`/`unconfirmed` 不可混为「已完成并已核实」）。
   - `health.channels`：每个通道/绑定一条 `{ channel, appIdMasked, lastProbeAt, status, capabilitiesSummary }`；未知字段用 `null`，不要编造。
   - `health.sessions`：观察名单每项 `{ sessionId, label, lastReadAt, capturedThroughSeq, lastEventAt, lastEventType, runState: 'unknown' }`。
3. `refreshSessions: true` 时先调用 `sessionProbe.refresh({ ownerId })` 再做汇总；`false`（默认）时只用库里的上次快照，并在 `health.sessions` 里保留其原有的 `lastReadAt`。
4. 无数据时各数组为空、`range` 计数为 0，不抛错。
5. 新增工具 `nightdesk_overview`：参数 `{ refreshSessions?: boolean }`；返回上面的结构；并在 `output.render` 里额外产出**一段中文纯文本摘要**（`[{type:'text',text}]` 两条内容块：第一条 JSON，第二条人类可读摘要），摘要格式：
   ```
   今日（11月14日）：3 件到期 —— 08:00 高数作业；14:00 ...
   待我拍板：2 条 —— 「周五前交」时间未知，需要确认具体日期；QQ 通道缺少 QQBOT_APPID
   最近完成：1 条 —— 实验报告（手动标记完成）
   来源健康：QQ 上次探测 2026-11-14 21:40 未通过（缺凭据）；观察中会话 2 个，最后读取 22:10
   ```
   摘要必须如实反映状态：`accepted` 不写成「已送达」，`unconfirmed` 不写成「已完成」。
6. 纯 ESM JavaScript、零第三方依赖、不 import 任何 `@deepseek-ai/*`；不做 commit/push。
