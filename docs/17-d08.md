# D08 实现简报：单 worker 受管委派（v0.3 本地草稿）

本文件是本次实现的契约。只实现本文件写明的范围，不做额外重构，不改产品文档（除本文件要求更新的 `docs/06`、`docs/16` 的进度段落）。

## 目标

在 `E:\Agents Dev\nightdesk\packages\dsh-nightdesk` 里加入「受管委派」：用户把一件工作交给一个 worker，worker 只产出**本地草稿**；代码负责授权、版本、预算、返工轮次、停止与审计，模型负责写草稿内容。必须能回答四个问题：谁授权、哪个 attempt、哪一版目标、能不能覆盖当前成果。

不做（明确边界）：

- 不真的起子进程/子会话，不递归委派（`delegate` 类工具一律视为未授权工具，创建任务时拒绝）。
- 不做多 worker、不做队列租约、不做远程执行、不写宿主 dsh 数据库。
- 不把「自然语言说完成了」当作回执：完成判定只看结构化提交 + 核对结果。

## 数据模型（schema_version = 5）

在 `src/store.js` 的迁移里新增（保持现有幂等风格，已有表不动）：

```sql
CREATE TABLE IF NOT EXISTS tasks (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  objective TEXT NOT NULL,
  inputs_json TEXT NOT NULL,          -- 输入引用数组 [{kind,id,label?}]
  allowed_tools_json TEXT NOT NULL,   -- 允许工具名数组
  scope TEXT,                         -- 允许改动的范围，可为空
  completion_rule TEXT NOT NULL,      -- 人工可读的完成规则
  acceptance_json TEXT NOT NULL,      -- 验收条目数组
  budget_json TEXT NOT NULL,          -- {maxAttempts, maxReviewRounds, maxDraftChars}
  goal_version INTEGER NOT NULL,
  status TEXT NOT NULL,               -- drafting|submitted|needs_revision|accepted|exhausted|stopped|canceled
  version INTEGER NOT NULL,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS task_attempts (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  task_id TEXT NOT NULL,
  attempt_no INTEGER NOT NULL,
  goal_version INTEGER NOT NULL,
  input_version INTEGER NOT NULL,
  status TEXT NOT NULL,               -- drafting|submitted|accepted|superseded|stale|stopped
  is_current INTEGER NOT NULL DEFAULT 1,
  draft_text TEXT,
  resources_json TEXT,                -- 用量/引用等结构化记账
  submitted_at TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE (task_id, attempt_no)
);

CREATE TABLE IF NOT EXISTS task_reviews (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  task_id TEXT NOT NULL,
  attempt_id TEXT NOT NULL,
  round INTEGER NOT NULL,
  verdict TEXT NOT NULL,              -- pass|needs_revision
  structure_ok INTEGER NOT NULL,
  evidence_ok INTEGER NOT NULL,
  content_ok INTEGER NOT NULL,
  findings_json TEXT NOT NULL,        -- [{id,severity,problem,requiredFix}]
  created_at TEXT NOT NULL
);

CREATE TABLE IF NOT EXISTS task_artifacts (
  id TEXT PRIMARY KEY,
  owner_id TEXT NOT NULL,
  task_id TEXT NOT NULL,
  attempt_id TEXT NOT NULL,
  kind TEXT NOT NULL,                 -- draft|note
  content TEXT NOT NULL,
  sha256 TEXT NOT NULL,
  created_at TEXT NOT NULL
);

CREATE INDEX IF NOT EXISTS task_attempts_current ON task_attempts(task_id, is_current);
```

所有写入沿用现有 `transaction()` + `BEGIN IMMEDIATE` 模式；时间统一 `now()` 注入的 RFC3339 毫秒 UTC 字符串（沿用 store 现有 helper）。

## 模块契约：`src/delegation.js`

```js
export const DELEGATION_ERRORS = {
  INVALID_ARGS: 'INVALID_ARGS',
  UNAUTHORIZED_TOOL: 'UNAUTHORIZED_TOOL',
  RECURSIVE_DELEGATION: 'RECURSIVE_DELEGATION',
  BUDGET_EXCEEDED: 'BUDGET_EXCEEDED',
  VERSION_CONFLICT: 'VERSION_CONFLICT',
  STALE_ATTEMPT: 'STALE_ATTEMPT',
  STALE_GOAL: 'STALE_GOAL',
  TASK_STOPPED: 'TASK_STOPPED',
  REVIEW_ROUNDS_EXHAUSTED: 'REVIEW_ROUNDS_EXHAUSTED',
  DUPLICATE_REVIEW: 'DUPLICATE_REVIEW',
  NOT_FOUND: 'NOT_FOUND',
};

export function createDelegation({ store, now, config }) { ... }
```

`config` 默认值：`{ maxAttempts: 5, maxReviewRounds: 2, maxDraftChars: 20000, maxInputs: 20, maxTools: 8 }`。

返回对象方法（全部同步，抛 `Error` 时 `error.code` 用上面的常量）：

1. `createTask({ ownerId, objective, inputs, allowedTools, scope, completionRule, acceptance, budget, goalVersion })`
   - 校验：`objective` 去空白后非空且 ≤ 2000 字符；`inputs` 是数组且 ≤ config.maxInputs，每项必须有 `kind` 与 `id`；`allowedTools` 数组 ≤ config.maxTools，全部必须出现在 `config.knownTools`（由 index.js 传入当前注册工具名集合），且不得包含 `nightdesk_task_create|nightdesk_task_start|nightdesk_task_submit|nightdesk_task_review|nightdesk_task_stop` 与任何 `delegate`/`subagent`/`spawn` 字样（命中 → `RECURSIVE_DELEGATION`）；未知工具 → `UNAUTHORIZED_TOOL`；`acceptance` 至少 1 条；`goalVersion` 必须整数 ≥ 1。
   - `budget` 与默认值合并，任一项超上限 → `BUDGET_EXCEEDED`。
   - 写 `tasks`（status `drafting`，version 1）+ 审计 `nightdesk.task_created`。

2. `startAttempt({ ownerId, taskId, goalVersion })`
   - 任务必须属于该 owner 且 `status ∈ drafting|needs_revision`；`goalVersion` 不等于任务当前 `goal_version` → `STALE_GOAL`；`stopped/canceled` → `TASK_STOPPED`；当前已存在 `is_current=1` 的 attempt 且状态 `drafting` → 直接返回该 attempt（幂等，不新建）；attempt 数已达 `budget.maxAttempts` → `BUDGET_EXCEEDED`。
   - 新建 attempt：`attempt_no` 递增，`input_version` = 任务的 `version`，`status='drafting'`，置旧 attempt `is_current=0` 且状态保留审计含义。
   - 审计 `nightdesk.attempt_started`。

3. `submitDraft({ ownerId, taskId, attemptId, goalVersion, expectedTaskVersion, draftText, resources })`
   - 校验顺序（顺序即错误优先级，测试会断言）：任务存在 → `status` 不能是 `stopped/canceled`（`TASK_STOPPED`）→ `goalVersion` 必须等于任务当前 `goal_version`（`STALE_GOAL`）→ `expectedTaskVersion` 必须等于任务 `version`（`VERSION_CONFLICT`）→ attempt 必须属于该任务且 `is_current=1` 且 `status='drafting'`（否则 `STALE_ATTEMPT`）→ attempt.goal_version 必须等于传入 goalVersion（`STALE_ATTEMPT`）→ `draftText` 去空白非空且长度 ≤ `budget.maxDraftChars`（`INVALID_ARGS`）。
   - 成功：写 `task_artifacts`（kind `draft`，sha256），attempt 置 `submitted` + `submitted_at`，任务置 `submitted`、`version+1`，审计 `nightdesk.draft_submitted`（带 attemptId 与 sha256）。

4. `review({ ownerId, taskId, attemptId, verdict, structure, evidence, content, findings })`
   - 只允许核对**当前** attempt 的最新提交，且该 attempt 必须是 `submitted`；重复核对同一 attempt 且上一轮已 pass → `DUPLICATE_REVIEW`。
   - `verdict='pass'` 要求三层全部为真（`structure.ok && evidence.ok && content.ok`）且 `findings` 为空，否则 `INVALID_ARGS`；`pass` 后任务置 `accepted`、attempt 置 `accepted`、`is_current=1` 保留，审计 `nightdesk.task_accepted`。
   - `verdict='needs_revision'` 必须至少 1 条 finding，每条含 `severity`（low|medium|high|blocker）、`problem`、`requiredFix`；写入 review 行，`round` 递增；任务置 `needs_revision`、`version+1`，attempt 保留 `is_current=0`（下一次 `startAttempt` 会建新 attempt）。
   - 轮次用尽：若该任务已有 `maxReviewRounds` 条 `needs_revision` 且再次 `needs_revision` → 任务置 `exhausted`，审计 `nightdesk.task_exhausted`，错误码 `REVIEW_ROUNDS_EXHAUSTED`（先写审计与状态，再抛错，保证可查询）。`exhausted` 后 `startAttempt` 拒绝（`REVIEW_ROUNDS_EXHAUSTED`）。

5. `stop({ ownerId, taskId, reason })`
   - 任务不存在或不属于该 owner → `NOT_FOUND`。已是 `stopped` 直接返回（幂等）。`accepted` 任务不允许 stop（`INVALID_ARGS`）。
   - 事务内：任务置 `stopped`、`version+1`；当前 attempt 置 `stopped`、`is_current=0`；审计 `nightdesk.task_stopped`（reason 截断 200 字符）。停止后再 `startAttempt`/`submitDraft` → `TASK_STOPPED`。

6. `requestChange({ ownerId, taskId, goalVersion })`
   - 目标版本变化时调用：任务 `goal_version` 更新为新值、`version+1`、所有当前 attempt 置 `stale` 且 `is_current=0`、任务状态回 `drafting`，审计 `nightdesk.goal_changed`。旧 attempt 再提交 → `STALE_ATTEMPT`。

7. `list({ ownerId, status })` → 任务数组（含 `currentAttempt` 摘要，不含 draft 正文）。

## 工具（`src/tools.js` 新增，全部 `definition()` 风格，参数用原生 JSON Schema 并自行校验）

- `nightdesk_task_create`：必填 `objective`、`acceptance`（数组）；可选 `inputs`、`allowedTools`、`scope`、`completionRule`、`budget`、`goalVersion`（默认 1）。
- `nightdesk_task_start`：`taskId`、可选 `goalVersion`（默认取任务当前值）。
- `nightdesk_task_submit`：`taskId`、`attemptId`、`draftText`、`expectedTaskVersion`（必填）、可选 `goalVersion`、`resources`。
- `nightdesk_task_review`：`taskId`、`attemptId`、`verdict`、`structure`/`evidence`/`content`（`{ok:boolean, note?:string}`）、可选 `findings`。
- `nightdesk_task_stop`：`taskId`、可选 `reason`。
- `nightdesk_tasks`：可选 `status`。

工具输出统一是结构化 JSON（`output.render` 返回 `[{type:'text',text:JSON.stringify(value,null,2)}]`），错误结果也必须是结构化对象 `{ok:false, code, message}` 而不是抛出未处理异常（沿用现有 tools.js 的错误包装方式）。

`index.js`：构造 `createDelegation({ store, now, config: { knownTools: <注册时收集的工具名数组> } })`，注入 `createTools({ store, scheduler, channel, sessionProbe, overview, delegation })`。注册顺序：先收集所有工具名再建 delegation，避免 knownTools 缺项。

## 测试（必须新增 `test/delegation.test.js`，并 import 进 `test/index.js`）

用真实 store（临时目录，沿用现有测试的 `mkdtemp` 风格），覆盖至少 18 项：

1. 创建任务成功，默认 budget 与 goalVersion=1。
2. 未知工具 → `UNAUTHORIZED_TOOL`。
3. `allowedTools` 含 `nightdesk_task_submit` 或 `subagent` → `RECURSIVE_DELEGATION`。
4. 空 objective / 空 acceptance → `INVALID_ARGS`。
5. `startAttempt` 幂等：连续两次返回同一 attemptId。
6. `submitDraft` 成功写入 artifact，sha256 与正文一致，任务 version 递增。
7. 用过期 `expectedTaskVersion` 提交 → `VERSION_CONFLICT`。
8. 用旧 attempt 提交 → `STALE_ATTEMPT`（T22）。
9. `requestChange` 后旧 attempt 提交 → `STALE_ATTEMPT`，且任务 `goal_version` 已是新值（T21）。
10. `goalVersion` 不匹配 → `STALE_GOAL`。
11. `stop` 后 `startAttempt` → `TASK_STOPPED`；`stop` 幂等。
12. `stop` 与派发竞争按事务顺序：`stop` 后立即 `submitDraft` → `TASK_STOPPED` 且没有新增 artifact（T27）。
13. `review` pass 需三层全真，缺一层 → `INVALID_ARGS`。
14. pass 后任务 `accepted`，再 review 同一 attempt 已 pass → `DUPLICATE_REVIEW`。
15. `needs_revision` 无 findings → `INVALID_ARGS`。
16. 两轮 `needs_revision` 后第三次 → `REVIEW_ROUNDS_EXHAUSTED`，任务 `exhausted` 且能查询到历史 review（保留已完成部分与未满足条件）。
17. 超出 `budget.maxAttempts` 的限制生效。
18. 两个 owner 相互隔离：A 看不到也不能操作 B 的任务（`NOT_FOUND`）。
